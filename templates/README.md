# IntraStack CRM CSV import template pack

These files are examples for Odoo 17 Community. Replace every example email,
login, date, URL, price, PO and External ID namespace as required. Always run
**Test** in Odoo before importing production data.

## Recommended import order

| Order | File | Import target |
|---|---|---|
| 1 | `crm_companies_import.csv` | Contacts — customer companies |
| 2 | `crm_contacts_import_template.csv` | Contacts — people related to companies |
| 3 | `crm_candidates_import.csv` | Contacts — individual candidates |
| 4 | `crm_recruiter_vendors_import.csv` | Contacts — recruiter/vendor companies |
| 5 (optional) | `banks_import.csv` | Contacts/Accounting configuration — Banks |
| 6 (optional) | `contact_bank_accounts_import.csv` | Bank Accounts linked to customer companies |
| 7 | `employees_import.csv` | Employees — employee master data only |
| 8 | `crm_opportunities_import.csv` | CRM Opportunities |
| 9 | `staffing_requirements_import.csv` | CRM → Staffing Operations → Requirements |
| 10 | `staffing_candidate_submissions_import.csv` | Candidate Submissions |
| 11 | `staffing_interviews_import.csv` | Interview Schedule |
| 12 | `staffing_placements_import.csv` | Placements |

## Important dependencies

- Import companies before contacts because contacts use
  `Related Company/External ID`.
- Opportunity customers must already exist.
- Requirements accept only opportunities classified as **Staffing**.
- Candidates and recruiter vendors must exist before Candidate Submissions.
- Submission and Requirement External IDs must exist before Interviews or
  Placements.
- `Recruiter/Login`, `Internal Interviewers/Login` and
  `Placement Manager/Login` must match active internal Odoo user logins.
- Datetimes are interpreted using the importing user's timezone. Review the
  preview before import.

## Bank data

Do not map `bank_ids/bank` or `bank_ids/acc_number` while importing Contacts.
Odoo may auto-map these technical headers to an unrelated accounting field and
then treat a SWIFT/BIC value as a record name. Import bank information in two
separate passes instead:

1. Import `banks_import.csv`; each SWIFT/BIC must identify one Bank record.
2. Import `contact_bank_accounts_import.csv`; link Account Holder and Bank by
   External ID.

If bank data is not needed for CRM operations, leave both contact bank columns
unmapped and exclude them from the source file.

The file `crm_contacts_import.csv` in this workspace may be a real customer
workbook uploaded for migration and is intentionally not included in the ZIP
template pack. A file beginning with ZIP/XLSX magic bytes (`PK`) is an Excel
workbook even if its filename ends in `.csv`; rename it to `.xlsx` or save it as
an actual CSV UTF-8 file before distribution.

## Employee import limitation

The employee CSV creates employee master records and assigns the IntraStack
Role field. It does not securely create user credentials. After import, an HR
Manager must open each Employee and use:

1. **Create Internal User**
2. **Sync IntraStack Access**
3. **Resend Invitation**, if required

## Workflow state rule

The operational templates intentionally omit the Status field. Records are
created in their safe initial state and must progress using workflow buttons.
Do not bulk-import Interviews as Completed or Placements as Confirmed/Active;
doing so bypasses feedback, contract, date and margin checks.

## Records that should not be imported for normal operations

- Quotations/Sales Orders should be created from the CRM opportunity so the
  correct template and traceability links are applied.
- Delivery Projects should be generated by confirming the linked Sales Order.
- Project template tasks are cloned automatically.
- Current timesheets should be entered by users against the generated project
  and task. Historical timesheet migration requires a separate controlled plan.
